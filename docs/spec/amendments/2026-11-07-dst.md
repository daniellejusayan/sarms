# Amendment A-2026-11-07-3 — deterministic simulation testing in the evaluation protocol (additive)

Applies to `docs/spec/evaluation-protocol.md`. Adds a verification method and a report; moves no target.

Deterministic simulation testing (`src/sarms/sim/`, `sarms dst`) drives the real code with seeded repositories and
scripted models through a written scenario grammar (feature, cross, repair, keep, bulk, split, rename, birth, death,
cycle, burst, quiet, revert_fix; eleven named scenarios and every ordered pair of two events). After every step it
checks invariants I1–I9 (push lands; no applied fix adds a violation; nothing left standing silently; ledger replayable;
one-commit revert; adoption touches nothing; set consistent; re-certification idempotent; certificates sound) and
labels each run CRITICAL / HIGH / MEDIUM / LOW. Level 1 runs in memory (ledger, certificate engine, enforcement
decisions); level 2 materialises a real git repository and runs the Differ, draft step, gate and kernel.

Reported: `reports/dst-risk.md` (scenario x label matrix, every CRITICAL/HIGH with its seed, coverage of events and
loop transitions). Target: 0 CRITICAL at the reported seed count. Human review of rules is removed from the protocol
(decision of 4 Nov 2026); the post-hoc audit of ledger episodes stays.
